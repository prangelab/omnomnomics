***OMNOMNOMICS!***

_Omnomnomics is an A-Z processing of RNA-, ChIP-, or ATAC-seq data. Trim FASTQ files, run FASTQC, map to the genome, and post-process the BAM files._

Usage: OMNOM_HOME/run_omnomnomics.py -i <EXPERIMENT_DIR> -t TYPE -g GENOME

Quickstart:
In a rush? You should be able to run these 2 steps easily from OMNOM_HOME.
```
module load snakemake
python(3) run_omnomnomics.py -i path/to/your/experiment_dir -t type_of_your_experiment -g genome_to_use ```

OMNOM_HOME, is the directory containing omnomnomics. This is where you installed omnomnomics and where the wrapper script, main snakefile, bin folder, genomes and slurm_profile are. The default directory structure generated and used by the pipeline is the experiment directory.  This is the main input directory containing your experiment and all your files folders. 
The FASTQ folder (inside your EXPERIMENT_DIR) contains raw FASTQ files. These should be created by you, and are used by one of the 'read trimming' jobs. The trimmed_FASTQ folder (inside your experiment directory) contains adapter trimmed FASTQ files, the output of the read trimming steps. 
The trimmed reads are then used by fastqc and mapping jobs.The folder fastqc_reports contains the QC reports (html and zip). 
The BAM folder contains raw BAM files, generated by one of the mapping jobs. These are then used by 'touchup_bam' job to produce sorted, duplicate read marked (or removed), and filtered BAM files in the filtered_BAM folder. 
In its turn, the filtered BAM files can be used by the 'index BAM', 'BAM stats', 'create HOMER tagDirs','call peaks' and 'count reads' jobs.
The index BAM job creates a bam.bai file for every sample. 
The folder HOMER_tagDirs contains HOMER tag directories generated by the 'create HOMER tagDirs' job. These HOMER_tagDirs are then used by the 'create BigWigs and TrackHubs' and 'create count table' jobs.
The folder BigWigs contains the BigWigs and TrackHubs generated by the 'create BigWigs and TrackHubs' job. 
The DE_calling folder contains count table and DE calling results for RNA-seq experiments, generated by the'Create count table' job (from HOMER_tagDirs) and next used by 'Call DE genes' job. 
Lastly, the folder peak_calling contains peak files for ChIP and ATAC epxeriments, generated by the 'call peaks' job from HOMER_tagDirs and filtered BAM files.


Workflow:
```Pre-processing steps:
1:	PREP: 	Trim FASTQ files
2:	QC:   	Run FastqQC
3:	MAP:  	Align reads to the genome
4:	MERGE:	Merge flowcell lanes (if needed; i.e., if samples were spread over multiple lanes (L00n) to meet the required seq depth)

Post-processing steps:
5:	Touchup BAM
			Runs a chain of samtools commands to sort, mark duplicate reads, and filter the BAM files
			Specifically: samtools collate | fixmate -m | sort | markdup (-r) | view -q 15
				All:	MAPQ > 15
				ChIP:	discard duplicates (-r)
				ATAC:	Get chrM stats
6:	Index BAM
7:	Generate read # statistics with bamtools stats
8:	Create HOMER tag directories
9:	Create BigWigs and trackHubs
10:	Merge Bigwigs and trackhubs by experimental group. Optional, will even in 'auto' mode only be run if the -E flag is set. See below.

Assay dependent follow-up steps:
11:	ChIP/ATAC: Call peaks
12:	RNA/ATAC:	   Create count table
13:	RNA/ATAC:	   Call DE genes/peaks


Auto mode:
	By default runs the whole pipeline. i.e., sets mode to 'all'
	Will detect an aborted run (e.g. cancelled by user using scancel or requeued by slurm due to resouce constraints)
	If an aborted run is detected, 'auto' mode will restart the run after the last succesfully completed step.
	If you wish to force a clean rerun, specify the mode explicitly or delete the omnomnomics.semaphore file from your experiment dir.

Some job mode examples:
	--job=all:	Run the whole pipeline 
					Input is the 'FASTQ' folder inside your <EXPERIMENT_DIR>, which contains the .fastq.gz files you want analysed.
	--job=1-3:	Run the pipeline up to and including the mapping step.
					Input is the 'FASTQ' folder inside your <EXPERIMENT_DIR>, which contains the .fastq.gz files you want analysed.
	-j 1-10:	Run the whole pipeline excluding the assay dependent follow-up.
					Input is the 'FASTQ' folder inside your <EXPERIMENT_DIR>, which contains the .fastq.gz files you want analysed.
	-j 4-12:	Run The whole pipeline, starting after the mapping step.
					Input is the 'BAM' folder inside your <EXPERIMENT_DIR>, which contains the raw .bam files you want analysed.
	--job=8-9:	Only generate HOMER tag directories and BigWigs.
					Input is the 'filtered_BAM' folder inside your <EXPERIMENT_DIR>, which contains the .bam files you want analysed.
	--job=7:	Only run the bamtools stats step to genrate some statistics.
					Input is the 'filtered_BAM' folder inside your <EXPERIMENT_DIR>, which contains the .bam files you want analysed.
	--job=1-9,11-13:	Run everything but do not create merged trackhubs.
					Input is the 'FASTQ' folder inside your <EXPERIMENT_DIR>, which contains the .fastq.gz files you want analysed.
	--job=1,3,5,6,8,11-13:	Trim the reads, map, touch up, create index and tagDirs, and run the assay dependent follow-up. Skip QC, merging and bigwigs
					Input is the 'FASTQ' folder inside your <EXPERIMENT_DIR>, which contains the .fastq.gz files you want analysed.```

Help Message:

    -i <EXPERIMENT_DIR>:    Main directory containing your experiment.
                                    Required argument
    -t TYPE:                Type of experiment: RNA, ChIP, ATAC
                                    Required argument
	  -g GENOME:				Genome version. Avaliable versions:
								UCSC/RefSeq/NCBI:	mm10, mm39, hg38.
								ENSMBL/GenBank:		GRCh38.p14, GRCm39
								Required argument
    -X:                     eXclude multiQC stats aggregator. Set if you don not wish to run multiQC.
    -j MODE:                Job mode. Can be 'auto', 'all' or a range of jobs. See below (-h) for some 
							examples.
                                    Default: auto
    -T TOOL:                Trimming tool choice. can be Skewer or Trimmomatic
                                    Default: Skewer
    -M TOOL:                Mapping tool choice. Can be HISAT2, STAR, or STAR_TE. STAR(_TE) can only be used 
							for RNA-seq data.
                                    Default: HISAT2
    -f DESIGN_FORMULA:      RNA: Experimental Design for DE calling
                                    Default: 1 (just an intercept)
    -I <INPUT>:             Input file used for ChIP peak calling. Has to be a .bam file or HOMER tag 
							directory.
                                    Default: Do not use input.
    -m <METADATA_TABLE>:    .txt file with columns of metadata for RNA-seq experiments.
                                    DESeq2 style metadata table describing all samples. Rownames should be 
							samplenames
	  -b:						ChIP: Peak calling style. If set, use MACS3 in --broad mode, and use HOMER findPeaks with -size, -minDist and -region settings. Works best with STYLE histone.
  	-S STYLE:				ChIP: Peak calling style for HOMER peak calling. Can be factor or histone.
								Default: factor
  	-z SIZE:				Minimum peak size. Used for defining peaks in HOMER broad peak calling mode.
								Default: 500
	  -d MINDIST:				Minimum distance bewteen peaks. Used for merging regions in HOMER broad peak calling mode.
								Default: 2000
								
      File name field settings for merged trackhubs, peak calling, and read counting. See below (-h) for some 
  	  examples
    -n FIELDS:              Field(s) in filename to use as track name, peak file name, and column header in the 
							count table
                                    Default: 1-3
    -e FIELDS:              Field(s) in filename to use as merged hub or peak calling group identifier
                                    Default: 1
                                    Creates separate merged hubs for each unique entry
    -c FIELDS:              Field(s) in filename to use as color type
                                    Default: 2
    -s CHAR:                Separator used in file names.
                                    Default: _
    -a STR:                 Appendix to add to track name
                                    Default: hub
    -C <Color_Table_FILE>:  File specifying which colors to use for the tracks
                          	  Default: gray.tint.color.table
                            Can be a *txt list file with one color table per line. Different color tables will 
							be used per hub as split by -t.
                            Can be a full (relative) path to a file or a file basename only in conjuction with 
	  -P.
                            Use createTrackColorTable.sh to roll your own or use one of the many presets in the 
							~/bin/color_data_for_hubs folder.
                            Use displayTrackColorTable.sh to visualize existing color tables.
    -P <DIR>:               Path to a folder with color tables.
                                    Default: bin/color_data_for_hubs
    -o:                     Overlay type (transparent|stacked|solid|none)
                                    Default: transparent
    -L:                     Email to use in trackhub
                                    Default: m.dewinther@amsterdamumc.nl

    -h:                     Print elaborate usage information
